## 2. 추가할 영상

실행 시 각 판이 mp4로 저장된다. 화면은 4분할이며 **아래 두 장이 정책에 실제로
입력되는 224 × 224 영상**이다. 위 두 장은 원본 카메라 영상이다.

### 2-1. 권장 네 편

| 저장소 경로 | 원본 경로 | 보여주는 것 |
|---|---|---|
| `docs/media/pipeline.gif` | `<work>/vid_abc/` 의 성공 판 (아래 선정 방법 참조) | 접근 → 파지 → 상승 전체 |
| `docs/media/topple.gif` | `<work>/vid_abc/abcB_09_dx-0.030_dy+0.059_r1.mp4` | 정책이 물체를 넘어뜨리는 실패 (12스텝에 종료) |
| `docs/media/no_grasp.gif` | `<work>/vid_abc/abcC0_03_dx-0.060_dy-0.019_r1.mp4` | 스크립트 IK가 문턱을 만족하지 못해 파지 명령을 내지 않는 실패 (90스텝 소진) |
| `docs/media/aim_offset.gif` | `<work>/vid_abc/abcC_01_dx+0.003_dy-0.045_r1.mp4` | 조준 보정 공유로 41 mm 옆을 무는 실패 |

두 번째와 세 번째를 나란히 두는 것이 이 실험의 요점이다. 두 조건은 성공률에서
구분되지 않지만 실패하는 방식이 다르다.

### 2-2. 성공 판 선정

성공 판의 파일명은 무작위 좌표에 따라 달라지므로 로그에서 찾는다.

```bash
cd <work>
grep -l "ok=1" gridlogs_abc/abcC0_*.log | head -3
```

출력된 로그 파일명에서 확장자만 바꾸면 대응하는 영상이 된다.

```
gridlogs_abc/abcC0_05_dx+0.012_dy-0.031_r1.log
        ->  vid_abc/abcC0_05_dx+0.012_dy-0.031_r1.mp4
```

### 2-3. 변환

저장소에는 mp4 대신 짧은 GIF를 넣는다. 용량이 작고 문서에서 바로 재생된다.

```bash
ffmpeg -i <원본>.mp4 -vf "fps=10,scale=480:-1" -loop 0 <저장소>/docs/media/<이름>.gif
```

원본 mp4 전체는 저장소에 넣지 않는다. 대표 영상 몇 개만 넣고,
나머지는 로그와 함께 별도 보관한다.

### 2-4. 캡션 규칙

영상에는 반드시 **판 번호와 좌표**를 캡션으로 적는다. 로그와 대조가 가능해야
영상이 근거로 기능한다.

```markdown
![물체 전도](docs/media/topple.gif)

*조건 B, 판 09, 물체 오프셋 dx −30 mm / dy +59 mm. 12스텝에서 물체 전도로 종료.*
```

## 3. 검출 진단 이미지

검출 결과 오버레이 이미지는 진단용 환경변수를 지정하면 저장된다.

| 원본 경로 | 내용 |
|---|---|
| `<work>/probe/det.png` | 검출 마스크가 초록으로 겹쳐진 wrist 영상 |

`ray`와 `top` 두 방식의 오버레이를 나란히 넣으면 §4의 검출 비교를 보완한다.
저장소에는 `docs/media/detect_ray.png`, `docs/media/detect_top.png`로 넣는다.
