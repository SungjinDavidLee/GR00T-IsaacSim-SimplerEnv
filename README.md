# Isaac Sim × GR00T N1.7 — 제로샷 파지 연동 및 한계 측정

Isaac Sim 6.0.1 에서 **NVIDIA GR00T N1.7** 을 Franka Panda 에 연동하고,
그리퍼 장착 RGB-D 카메라 **한 대**만으로 물체를 집어 올리는 실험 환경입니다.
**GR00T 의 가중치는 학습시키지 않았습니다(제로샷).**

> 이 문서는 **직접 측정한 값만** 적었습니다.
> 미완성·미검증·무효 처리된 실험은 §8 에 전부 명시했습니다. 숨긴 것은 없습니다.

---

## 0. 이 프로젝트를 한 문장으로

> **Isaac Sim 에서 GR00T N1.7 의 제로샷 파지를 Franka 에 연동하고,
> GR00T 의 공간 조건화(spatial grounding) 한계를 측정한 뒤,
> 외부 grounding 과 추론 시점 샘플링으로 보완한 실험 환경.**

아래 표현은 **사실과 다르므로 쓰지 않습니다.**

| 쓰면 안 되는 표현 | 왜 |
|---|---|
| ~~"GR00T 를 학습시켜 새 VLA 를 만들었다"~~ | 가중치를 건드리지 않았습니다 |
| ~~"GR00T 가 명령을 이해하고 스스로 물체를 찾아 잡는다"~~ | 대상 선택은 OWL-v2 가 합니다(§4-2, §6-4) |

## 1. 개발 경위 — 이 구조는 설계가 아니라 측정의 결과입니다

처음부터 OWL-v2 를 넣기로 계획한 것이 아닙니다.
**원래 목표는 GR00T N1.7 을 Isaac Sim + Franka 에 연동하는 것 하나였고**,
각 모듈은 측정으로 문제를 확인한 뒤 그 대응으로 추가됐습니다.

```
[1] GR00T ↔ Isaac Sim 연동
      목표: 제로샷 파지를 Franka 에서 동작시킨다
        │
        ▼
[2] GR00T 단독 공간 조건화 측정
      물체를 옮기고 그리퍼가 따라오는지 측정
      → 추종 이득 −3.6 % / −3 % / −13.6 %  (§6-3)
      → 물체가 움직여도 그리퍼가 따라가지 않음
        │
        ▼
[3] 원인 규명: 카메라 파라미터
      D405 공칭 87° 가정 → 위치 추정 오차 112 mm
      USD prim 실측 107.5° 적용 → 6.6 mm       (§6-1)
        │
        ▼
[4] 외부 grounding 추가
      자연어 → OWL-v2 로 대상 지목 → Depth 역투영 → 3D 위치
      그 위치로 state 프레임을 정렬                (§4)
        │
        ▼
[5] 정책 확률성 발견
      동일 관측으로 5회 호출 → 매번 다른 행동
      std 0.0136 / 범위 0.189                    (§6-5)
        │
        ▼
[6] 추론 시점 샘플링
      K=8 중앙값 → 조준 성공률 30 % → 93 %       (§6-5)
        │
        ▼
[7] 성능 측정
      캔 무작위 위치 7/8, 고정 위치 3/3          (§5)

**[2] 가 없었으면 [4] 는 없었습니다.** 순서가 이 프로젝트의 내용입니다.

## 2. 사용한 모델과 그 역할

| 모듈 | 종류 | 역할 | 왜 넣었나 |
|---|---|---|---|
| **GR00T N1.7** | **VLA** (3B, Qwen3-VL 백본 + flow-matching 액션 헤드) | **파지 행동 생성** | 이 프로젝트의 주 대상 |
| **OWL-v2** | VLM 검출기 (행동 생성 안 함) | 자연어로 **대상 물체 지목** | §6-3 에서 GR00T 의 공간 조건화가 작동하지 않음을 측정한 결과 |
| `can_detect.py` | 자체 코드 | 박스 + depth → **3D 위치** | 시뮬레이터 정답 좌표 조회를 대체 |
| **Lula IK** | 운동학 솔버 (AI 아님) | End-Effector 목표 → 7관절 각도 | 로봇 제어 파이프라인의 표준 구성 요소 |

**Lula IK 는 문제를 보완하려고 넣은 것이 아닙니다.**
GR00T 가 "손을 어디로 옮길지"를 내면, Lula 가 "그러려면 관절을 어떻게 돌릴지"를 계산합니다.
어떤 매니퓰레이터 파이프라인에도 이 계층이 있습니다.

## 4. GR00T 에 실제로 들어가는 것 — 정확히

이 부분을 뭉뚱그리면 오해가 생기므로 구현 그대로 적습니다.

### 4-1. 입력

```python
gobs = {
  "video": { "image":       <224×224×3 RGB>,   # front 슬롯. CAMMODE=wristdup 이라 wrist 복제본
             "wrist_image": <224×224×3 RGB> }, # wrist D405
  "state": { "end_effector_position": <3>,     # OFF 로 정렬된 프레임의 EE 위치
             "gripper": <2> },
  "annotation": "<지시문 텍스트>"
}
```

### 4-2. **3D 좌표는 GR00T 에 입력하지 않습니다**

검출로 얻은 물체 좌표는 GR00T 의 입력 텐서에 들어가지 않습니다.
대신 오프셋 `OFF` 를 만들어 **두 곳**에 씁니다.

```
OFF = RbT·(물체_추정_월드좌표 − 로봇베이스) − LIB_OBJ − bias
```

1. **홈잉 목표** — 에피소드 시작 시 팔을 세울 위치 `ee_goal = LIB_EE0 + OFF`
2. **state 프레임** — GR00T 에 보고하는 EE 위치 `lp = RbT·(EE − base) − OFF`

즉 **"좌표를 넣는다"가 아니라 "좌표로 상태 프레임을 정렬한다"** 입니다.
그 프레임에서 보면 물체는 항상 LIBERO 학습 위치에 있고, GR00T 는 학습 시 보던 상태 분포를
보게 됩니다. **depth 도 GR00T 에 들어가지 않습니다** — 체크포인트의 관측 스키마가 RGB 전용입니다.

### 4-3. 우리가 개입하는 지점

| 개입 | 내용 |
|---|---|
| 홈잉 | 에피소드 시작 시 팔을 초기 자세로 보내는 **스크립트 이동**. GR00T 아님 |
| 회전 3-DoF | `chunk[:,3:6]=0`, `target_q=q0` — **GR00T 의 회전 출력을 버립니다**(§8-3) |
| `ASCALE=0.05` | 행동 크기 배율 |
| `NSUBOPEN=2` | 청크 8스텝 중 접근 구간에는 2스텝만 실행 |
| `CLOSEMIN` / `GHOLD` / `NOREOPEN` | 닫기 시점·유지·재개방 차단 |
| 작업공간 클램프 | 목표 위치를 상자 안으로 자름 |
| `KSAMPOPEN=8` | 동일 관측 8회 호출 후 중앙값 |

**접근·하강·파지 자체는 GR00T 의 예측 행동입니다.** 대조 실험으로 확인했습니다(§6-6).

### 4-4. 행동이 관절 명령이 되기까지 — 한 스텝의 전 과정

```
[1] 관측 구성
    wrist RGB (1280x720) --crop--> 224x224      x2 (front 슬롯에 복제)
    EE 위치 --> lp = RbT(ee - base) - OFF       (정규화된 state)
    텍스트 --> annotation

[2] 정책 호출  (K=8 이면 8회 호출 후 중앙값)
    act = client.get_action(gobs)               ZMQ 5555
    act = { x, y, z, roll, pitch, yaw, gripper }   각각 길이 8 (청크)

[3] 청크 구성
    ch[:,0:3] = [x, y, z]                       LIBERO 프레임 병진 델타
    ch[:,3]   = -sign(2*gripper - 1)            gsig. < -0.3 이면 닫기
    ch[:,3:6] (회전) = 0                        ★ 버린다 (ROT6=0)

[4] substep 실행  (열림 구간 NSUBOPEN=2, 닫힘 구간 NSUB=8)
    for k in range(nuse):
        d = (ch[k,:3] * ASCALE).dot(RbT)        LIBERO -> 월드 델타
        target_p += d
        _l = RbT(target_p - g - base) - OFF
        _l = clip(_l, CLO, CHI)                 ★ 작업공간 클램프
        target_p = base + Rb(_l + OFF) + g
        target_p[2] = max(target_p[2], z_floor) ★ 하강 하한
        IK: compute_inverse_kinematics(target_p, target_q)
        robot.apply_action(joint_positions)      ARMONLY=1 이면 팔 7축만
        backend.advance_control_step()

[5] 그리퍼
    g = -ch[k,3]
    닫기: g < -0.3 이 GDEB 회 연속 && step >= CLOSEMIN  -> set_gripper(False), hold=GHOLD
    열기: hold 소진 후 g > 0.3      (NOREOPEN=1 이면 첫 파지 후 무시)

[6] 종료 판정
    물체 상승 > LIFTTH(0.08) -> ok=1        (PLACE=1 이면 여기서 끝내지 않음)
    물체 전도 -> abort=1                    (ABORT=1 일 때)
    step >= MAXSTEPS
```

**GR00T 가 내는 것은 [2] 뿐입니다.** [3]의 회전 폐기, [4]의 클램프·`z_floor`,
[5]의 디바운스·`GHOLD`·`NOREOPEN` 은 전부 하네스가 겁니다.

`ZEROACT=1` 로 [3]의 병진을 0 으로 만들면 팔이 하강하지도 파지하지도 못합니다(§6-6).
즉 **접근·조준·파지 타이밍은 GR00T 의 행동**입니다.

### 4-5. 좌표계 정리

```
월드         Isaac Sim 기준
로봇 베이스   bp = robot.get_world_pose(),  Rb ~ diag(-1,-1,1),  RbT = Rb 전치
LIBERO 프레임 lp = RbT(ee - bp) - OFF       정책이 보는 좌표계
카메라       USD prim 월드 변환, 광학축 규약 USD (+X right, +Y up, -Z fwd)
             fx = fy = 469.27  (1280x720)
```

부호 규약 (`AIM`, `CAMSHIFT` 공통):

```
+x  로봇에서 멀어지는 방향
-y  로봇 기준 오른쪽        (스펀지·캔에서 실측 확정)
+z  위
```

**주의:** `AIM` 의 y 부호는 물체·위치에 따라 반대로 나온 사례가 있습니다(페트병).
**부호는 항상 한 판 돌려 실측으로 정하십시오.**

## 6. 측정으로 밝힌 사실

### 6-1. D405 카메라 파라미터 — 초기 오차 112 mm 의 원인

USD Camera prim `/World/Franka/panda_hand/D405Mount/Camera_D405` 에서 직접 읽은 값:

```
focalLength 1.93,  hAperture 5.2644,  vAperture 2.9612
→ hFOV 107.5°,  vFOV 75.0°  →  fx = fy = 469.27  (1280×720)
축 규약: USD (+X right, +Y up, −Z forward)
depth: distance_to_image_plane, 미터 단위
```

D405 공칭 사양 87°(fx = 674.4) 를 가정했을 때 위치 추정 오차 **112 mm**,
USD 실측값 적용 후 **6.6 mm**.

> **교훈: 벤더 공칭값이 아니라 씬에서 직접 읽어야 합니다.**

### 6-2. `up` 과 `wrist` 는 같은 카메라

두 스트림의 배열이 `np.array_equal` 로 완전히 동일했습니다.
d405 prim 은 `panda_hand` 아래 하나뿐입니다. 키가 둘일 뿐 같은 손 카메라입니다.

### 6-3. GR00T 의 공간 조건화가 이 씬에서 작동하지 않음 ← 구조 변경의 근거

상태 프레임을 물체에 고정(`ANCHOR=fixed`)하고 물체만 옮겼을 때 그리퍼의 y축 추종 이득:

| 카메라 구성 | 이득 |
|---|---|
| front + wrist | **−3.6 %** |
| wrist 단독 (front 회색 마스킹) | −3 % |
| wrist 복제 (`wristdup`) | **−13.6 %** |

**세 구성 모두 0 또는 음수** — 물체가 이동해도 그리퍼가 따라가지 않고 오히려 반대로 갑니다.
`libero_spatial` 체크포인트로 교체해도 동일했습니다.

이 측정이 §1 [4] 의 근거입니다. **"OWL-v2 가 GR00T 보다 낫다"는 주장이 아니라,
"이 씬·이 체크포인트에서 GR00T 의 공간 조건화가 확인되지 않았다"는 사실**입니다.

### 6-4. GR00T 의 언어 조건화도 이 씬에서 확인되지 않음

지시문을 바꿔도 동작이 동일했습니다. 현재 GR00T 에 주는 지시문에는
`can` 이라는 단어가 없는데도 캔을 잡습니다.

> **한계: 육안 판정입니다.** 정량화하려던 스크립트에 결함이 있어 지시문이 잘려 전달됐고,
> 그 결과는 폐기했습니다(§8-5). **정량 수치는 없습니다.**

### 6-5. GR00T 의 액션 헤드는 확률적이다

**완전히 동일한 관측**으로 정책을 5회 호출한 결과:

```
행동 차원 112,  표준편차 평균 0.0136 / 최대 0.067,  범위 최대 0.189
```

flow-matching 계열 헤드가 호출마다 노이즈를 새로 샘플링합니다.
`ASCALE=0.05` 를 곱하면 substep 당 최대 9.5 mm 변동이며 관측된 파지 산포와 크기가 맞습니다.

**대응 — 추론 시점 샘플링:** 동일 관측에서 K=8 회 샘플링 후 **중앙값** 사용.
가중치를 바꾸지 않으므로 파인튜닝이 아니며, 추론 비용이 8배입니다.

| | 조준 성공률 | 파지 산포 |
|---|---|---|
| K=1 | ~30 % | dx 46 mm, dy 30 mm |
| **K=8** | **93 %** | **dx 9.3 mm, dy 12.3 mm** |

> **이 발견 전까지 n=3~4 판으로 파라미터를 비교했는데,
> 모든 조건의 신뢰구간이 서로 겹쳐 사실상 잡음을 신호로 읽고 있었습니다.**
> 해당 시기의 판정은 `deprecated/` 에 남기되 무효로 표시했습니다.

### 6-6. 파지 동작이 GR00T 의 예측임을 확인한 대조 실험

정책의 **병진 출력을 0으로 강제**(`ZEROACT=1`)하고 실행 → **팔이 하강하지 않고 파지 실패**.

→ 접근·하강·파지는 GR00T 가 예측한 행동이며, 홈잉이나 클램프가 대신하는 것이 아닙니다.

## 7. 우리가 조정한 것 전부와 그 이유

GR00T 가중치는 건드리지 않았습니다. 아래는 전부 **모델 바깥**의 조정입니다.

### 7-1. 카메라 캘리브레이션

| 값 | 출처 |
|---|---|
| `fx = fy = 469.27` | USD Camera prim 속성 |
| 카메라 자세 | 매 프레임 USD prim 월드 변환 조회 (실물에서는 FK) |
| `CAMSHIFT = -0.0180, 0.0283, 0` | 런타임에 `D405Mount` prim 을 손 프레임에서 이동 |

`CAMSHIFT` 가 필요한 이유: 정책이 wrist 영상 기준으로 손을 세우므로,
카메라를 옮기면 손이 그만큼 움직입니다(계수 **−0.686 mm/mm** 실측).
실물에서는 **카메라 브래킷 치수**에 해당합니다.

> `CAMSHIFT` x 는 **−0.0205 부터 모델이 아예 파지 명령을 내지 않습니다**
> (12판 전부 `close_step = −1`). 3.7 mm 만의 절벽이며 **원인 미규명**입니다.

### 7-2. 물체 상수 — **정답 좌표를 1회 사용했습니다**

| 물체 | `CANRK` | `CANZOFF` |
|---|---|---|
| can | 0.413 | −0.0416 |
| sponge | 0.040 | −0.0180 |
| bottle | 0.375 | −0.0495 |

`CANRK` 는 "보이는 표면 → 물체 중심축" 보정 계수, `CANZOFF` 는 z 보정입니다.
**시뮬레이터 정답 좌표와 비교해 1회 교정한 값입니다.** 캘리브레이션 성격이지만
**실물에는 정답이 없으므로 그대로 쓸 수 없습니다.**

제거용 코드(`DETGEOM=top` — 윗면 점구름 + 테이블 평면 기하)를 작성했으나 **미검증**(§8-2).

### 7-3. 조준 보정 상수 `AIM` — 사람이 영상을 보고 맞췄습니다

| 물체 | AIMX | AIMY | AIMZ |
|---|---|---|---|
| can | +0.0415 | **+0.004** | 0.000 |
| sponge | +0.025 | −0.050 | 0.000 |
| bottle | 0.000 | +0.034 | +0.095 |

검출 좌표는 정확한데(오차 0.2 mm) 파지점이 물체 중심에서 로봇 쪽으로 약 25 mm 치우칩니다.
**GR00T 가 LIBERO 에서 학습한 궤적의 계통 편향**이며 파라미터로 제거되지 않습니다.

> **정직하게 밝힙니다: 이 값들은 실행 영상을 사람이 보고 "조금 더 앞으로",
> "오른쪽으로" 같은 판단을 반복해 맞춘 것입니다.**
> 페트병 `AIMY` 만 두 측정점의 선형 보간으로 구했습니다. **자동 교정 절차는 없습니다.**

`AIMY` 는 8/21 에 0.008 → **0.004** 로 재교정했습니다(무작위 8곳 3/8 → 6/8).
0.012 로 반대 방향으로 밀었을 때는 더 나빠졌습니다. **부호는 실측으로만 정해집니다.**

### 7-4. 그 외 설정

| 항목 | 값 | 근거 |
|---|---|---|
| `KSAMPOPEN=8` | 접근 구간만 8샘플 중앙값 | §6-5 |
| `NSUBOPEN=2` | 접근 중 청크 2스텝만 실행 | 재질의 4배 → dx 산포 46→12 mm |
| `CLOSEMIN=4` | 4스텝 전 닫기 명령 무시 | 2·6 대비 실측 우세 |
| `GHOLD=24` (페트병 48) | 파지 후 유지 스텝 | |
| `NOREOPEN=1` (페트병) | 첫 파지 후 열기 명령 무시 | 물었다 놓는 극한주기 차단 |
| `CAMMODE=wristdup` | front 슬롯에 wrist 복제 | 카메라 1대 제약. 회색 마스킹보다 분포 밖 정도가 덜함 |
| `ABORT=1` | 물체 전도 시 조기 종료 | **정답 좌표 사용. 평가·시간절약 전용, 정책 입력 아님** |

## 8. 미완성·미검증 (숨기지 않음)

### 8-1. 페트병을 잡지 못합니다

최신 설정에서 조준은 크게 개선됐습니다(dy 오차 −29.4 → −7.7 mm, `nclose=1`, `abort=0`).
그러나 **3판 모두 들어올리지 못하고 `MAXSTEPS=90` 을 소진**했습니다(판당 약 230초).
뚜껑 근처를 무는 것까지는 되나 파지 유지·상승이 성립하지 않습니다. **원인 미규명.**

### 8-2. 물체 상수 제거는 코드만 있고 검증 안 됨

`DETGEOM=top`(`patch_candetect_geom.py`)을 작성했습니다.
윗면 점구름 중앙값으로 xy 를, 테이블 평면 대비 높이로 z 를 구해 `CANRK`/`CANZOFF` 를
없애는 방식입니다. **적용해 측정한 적이 없습니다. 실물 이식에 필수 항목입니다.**

### 8-3. 6-DoF 복원 판정 보류

`ROT6` off / RSCALE 0.05 / 0.02 를 4판씩 비교했으나 전부 0/4 였습니다.
**단 그 실험은 검출 좌표가 19 mm 어긋난 상태에서 수행되어 무효입니다.**
조준이 맞은 현재 상태에서 재측정해야 합니다.

### 8-4. 놓기(place) — 부분 구현. **하강은 GR00T 가 아니다**

집어서 **제자리에 내려놓기**까지 동작합니다(무작위 8곳 4/8). 다만 구성은 이렇습니다.

| 구간 | 누가 |
|---|---|
| 접근·조준·파지·들어올림 | **GR00T** |
| **하강·개방** | **폐루프 서보(`PLACESERVO`). GR00T 가 아님** |

`PLACESTEPS=0` 으로 두면 GR00T 의 놓기 구간은 0 스텝이며, 하강은 전적으로
우리 IK 서보가 수행합니다. 목표 높이는 집을 때 depth 로 측정한 물체 높이(`z_can0`)입니다.

**GR00T 는 놓기 동작을 내지 않습니다** `[확인]`. 지시문 5종
("put it down on the table", "lower the can and open the gripper",
LIBERO 학습 원문 포함)을 비교했으나 전부 lift 0.31~0.38 m 높이에서 개방했고
`perr` 0.091~0.146 로 서로 구분되지 않았습니다. **§8-5 의 정량 근거이기도 합니다.**

"옮겨서 놓기", "A와 B 사이에 놓기" 는 구현되어 있지 않습니다.
이송(좌우 이동)을 GR00T 가 수행하지 않기 때문입니다.

### 8-5. 언어 무효화의 정량 측정 없음

`lang_test.sh` 가 `while read` 루프 안에서 `python3` 에 stdin 을 뺏겨
지시문이 잘린 채 전달됐습니다(`"pick up the coke can..."` → `"ick up the can"`).
**해당 결과는 폐기했습니다.**

다만 **놓기 구간에서는 정량 측정이 있습니다**(§8-4). 지시문 5종의 `perr` 가
0.091 ~ 0.146 로 구분되지 않았습니다. 집기 구간의 정량 측정은 여전히 없습니다.

**어휘 주의:** 이 체크포인트는 LIBERO-Object 로 학습됐고 그 물체 이름은
alphabet soup / cream cheese / salad dressing / tomato sauce / ketchup / butter /
milk / orange juice / bbq sauce / chocolate pudding 입니다.
**"coke can" 은 학습 어휘에 없습니다.**

### 8-6. 표본 수와 데이터 손상

대부분의 조건이 n = 3~8 입니다. 무작위 캔 7/8 의 95 % 신뢰구간은 **53 ~ 98 %** 로 넓습니다.

무작위 시험 일부 판이 터미널 붙여넣기 결함으로 좌표가 손상됐습니다
(`dx=-0.0317` → `dx=317.0`). 해당 판은 무효 처리했으며,
**스크립트를 파일로 전달하지 않고 명령을 붙여넣은 것이 원인**입니다.

### 8-7. `fit` 지표는 참고용입니다

`fit` 은 임의로 정한 문턱(`|dx|<45, |dy|<6.3, |dz|<25` mm)입니다.
초기 버전은 **dy 만 검사**해서 dx 가 34 mm 어긋나도 `fit=1` 이 찍혔습니다.
그 시기의 "성공"은 전부 가짜였고 수정했습니다.
**물리 결과인 `ok`(상승 0.08 m)만 신뢰하십시오.**

### 8-8. 스펀지는 x 방향 이동에 약합니다

무작위 시험 실패 3판이 전부 \|dx\| > 30 mm, 성공 3판이 전부 \|dx\| < 20 mm 였습니다.
스펀지가 x 로 100 mm 길쭉해 조준 상수가 덜 견디는 것으로 보이나 `[추론]` 이며 미검증입니다.

### 8-9. **GR00T-only 대조 실험이 없습니다** ← 가장 중요한 공백

§6-3 은 "공간 조건화 이득"만 측정했고,
**동일 설정에서 `ANCHOR=fixed`(외부 grounding 없음) vs `ANCHOR=detect`(현재 구조)의
파지 성공률을 비교한 데이터는 없습니다.**

따라서 현재 문서는 **"외부 grounding 이 GR00T-only 보다 낫다"를 입증하지 않습니다.**
그 주장을 하려면 §9 의 실험이 선행되어야 합니다.

### 8-10. 사문화된 설정

| 항목 | 상태 |
|---|---|
| `XBIAS` / `YBIAS` | 213 mm 범위로 흔들어도 파지점이 4 mm 변함(기울기 0.004). **효과 없음** |
| `GLATCH` | 헤더에 출력만 되고 코드 어디에서도 사용되지 않음 |
| front D455 | `wristdup` 이라 실질 미사용 |
| `CANRAD` (스펀지·페트병) | 캔 값 0.0329 을 그대로 사용. `CANRK` 가 흡수하므로 무해하나 의미 없는 숫자 |
